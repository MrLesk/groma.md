## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Keep the byte limit in component naming because the component ID becomes a Markdown filename. Apply it to the full candidate before checking for collisions. The Groma application profile owns the ID rule for existing C4 components. The records retain standard OKF titles and Markdown links.
2. Replace the PR’s helper checks with a reconciliation test that writes and reloads components with long Unicode stems. Different extensions of the same stem exercise the source-path hash fallback. A distinct stem with the same long prefix covers shortening before a collision. The fork writes IDs over 160 bytes in that fallback, while its existing tests check shorter hash cases and compute a filename without writing it. Verify the byte limit, distinct owners, exact source files and stable IDs on rescan.
3. Reproduce the original failure and verify the fix using the CLI with a disposable deeply nested source fixture. Document the final ID rule, run the repository checks and review the complete PR.
