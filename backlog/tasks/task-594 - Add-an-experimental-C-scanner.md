## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Keep C++ as source evidence. Groma core owns C4 systems, containers, components and relationships; the scanner adds no architecture level or OKF metadata. Existing Markdown Code links remain readable without Groma.
2. Read only core-selected C++ files. Bundle Tree-sitter JavaScript/WASM and keep scanner selection, discovery and release packaging in existing integration points. Shared .h inputs alone do not prove a C++ project. Do not follow includes, evaluate build configuration, install project dependencies or run compiler/build tools during scans.
3. Keep responsibilities local: index.ts reads/cleans source trees and assembles observations; syntax.ts owns immutable parsing, failures and names; macros.ts owns selected definitions and bounded modifier/scope proofs; declarations.ts owns physical declarations, access and callers; outline.ts joins written declarations into Code details. Build and grammar-maintenance tools remain separate from scan runtime.
4. Preserve honest evidence. Retain physical UTF-16 positions and all parsed conditional possibilities. Join separate members only with written type/name/parameter-count access evidence; retain uncertainty for ambiguous overloads. Calls stay unresolved. Do not turn macros, deferred lambdas, casts or preprocessor conditions into runtime callees or generated declarations.
5. Admit reproduced ordinary C++ and explicit macro/conditional syntax through the pinned grammar overlay. Selected definitions may prove neutral modifiers, bounded scope effects, exact namespace/export delimiters or constrained fixed-prefix/suffix token pastes. Unknown owner/caller/access facts are omitted with diagnostics; unknown scope boundaries and invalid/unsupported syntax fail explicitly. No expansion, source rewriting, arbitrary recovery or configuration selection is used. Objective-C/embedded JavaScript and absent selected JSON definitions remain explicit OpenTTD boundaries.
6. Keep regression coverage tied to supported failures: operator/conversion identities; local and separate-member ownership; conditional access; full-library syntax; physical source after quoted directives; macro callable chains and caller/type escape depth; namespace/export boundaries; bounded paste controls; typed definitions versus typeless macro-shaped functions; literal member-name aliases preserving later written access. Extend existing tests with minimal before-fail/after-pass controls rather than duplicate layers. Preserve the unchanged upstream corpus and independent source probes.
7. Qualify the same seven pinned selections through packaged Groma install/scan/Code/source-owner flows, expected central responsibilities, source hashes/positions, repeatability and selected-input/offline/no-tools controls. Require all four original libraries plus Ninja/fmt to scan in full; keep the unchanged OpenTTD full-selection failure and its affected responsibilities visible. Complete own specification/quality review, the existing cold/final targeted review gates, and the final combined repository check. Document actual host execution and frozen package identity. Do not commit, publish or create a PR during this task handoff.
