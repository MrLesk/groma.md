## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The owner judged the first icon artwork on the live map on 2026-11-19 and rejected it: the objects were crude, the icon before a container title was enlarged until it stood larger than the buildings, and white screens and heavier lines made icons the brightest things on a grey map. The same day he pointed to the look he wants: fine isometric line drawings, quiet faces, and one part of each object picked out in an accent. This task redraws the icons in that look, makes an icon follow the name it stands before, and replaces the first 23 names with 141 generic names in 13 kinds.

The owner's decisions. 2026-11-19: the look; an icon lies in line with its text, is sized from it and is drawn whenever the text is. 2026-11-20: an icon is drawn once, as map geometry; the Iso and Layers views look at it from the map's angle and the 2D view looks at it from straight above with upright panels laid flat; the hierarchy, the details and the Icon field show the drawing of the 2D view; the switch between the two is hard and no line fades with the zoom; an object needs no base plate. 2026-11-21: the names are generic architecture parts that fit any repository, never Groma's own; they are derived from ten curated open source projects of different kinds, and Groma's own map uses a subset of them; after seeing all 141 drawings in both views he answered "Yes, land them".

The coordinator's choices, not his decisions: which names and kinds the list holds, how each object is drawn, every constant, the wording of the acceptance criteria, and the Icon field's kind names, filter box and named pick, which he saw as a mock before they were built.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Every named icon's object is drawn in lines of one fine width over quiet faces, and one part or the few marks that draw one thing are its accent
- [x] #2 The accent is drawn in ink; on an element or group with an authored color the accent takes that color and the rest of the object stays neutral
- [x] #3 An icon is sized from the letters of its name and changes with them: a title's icon follows the title's size step when the map is zoomed
- [x] #4 An icon is drawn whenever its name is drawn, at every zoom
- [x] #5 No icon's drawing before a title reaches a building on the surface behind it, at any size of the title
- [x] #6 An icon is the same drawing at every size: only the width of its lines follows the zoom
- [x] #7 An object shows only the faces turned to the reader at every orbit angle, and a curved wall shows no line between its segments
- [x] #8 The Light, Dark and Blueprint themes and the export covers draw the same objects
- [x] #9 The icon list holds 151 names in 13 kinds. Every name is a generic kind of part that any architecture can have, and every name has an object whose accent shows from both views
- [x] #10 groma edit --help lists the icon names one kind per line, and an unknown name is refused with a pointer to that list
- [x] #11 The web map documentation and the Markdown contract describe the look, the accent, the names by kind, and how an icon follows its name and the view
- [x] #12 The Markdown contract, the agent guide and groma edit --help tell an author to pick the icon of the area a part is about, not of the action it performs

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Part model (icons/parts.ts): one prism, a flat outline on the footprint raised straight up from height z by h: a sheet, a plate, a box, a cylinder. A ball is the only other part. A part or a mark can belong to the accent. An object lies on its footprint like a relief (x to the east, y to the south, z up). Nothing stands upright as a thin sheet: a picture that has a top lies face up with its top to the north, and is thick enough to show a wall (a sheet on the ground 0.08, a thick plate 0.12, a body 0.16, a detail on a part 0.05).
2. Visible faces (iso/painting/icon-faces.ts): from the reader's direction (towardsReader, beside project() in projection/project.ts) decide which walls of a prism face the reader and whether its top does, join walls along a curve into one face, shade a wall by screen side like a building, and order parts back to front: where two parts overlap, the one that reaches higher is drawn over the other, and overlapping parts of one height keep the order of the list. groundMiddle gives the middle of the ground an object covers.
3. Look (iso/painting/style.ts, scale.ts): quiet lines a little brighter than the map's outlines, faces a little off paper, the accent in ink. A colored element hands its color to the accent through --icon-accent in the browser and through explicit rules on a cover. One list of the authored color variables serves the zone reset and the comparison reset.
4. An icon is part of its name (sheet/measure.ts, iso/painting/text.ts, names.ts): its box is ICON_RATIO (0.9) font sizes wide, one gap before the text, on a roof's first line and before a title. A title's box is laid out with the title, so it follows the title's size step. A round roof centres its name, so there the box lies above the name, centred over it (iconAbove and roofIconSlot in sheet/measure.ts). Nothing is drawn larger than its box, and no rule hides an icon while its name is drawn.
5. One drawing per icon (iso/painting/icons.ts): iconSvg draws the object from the map's view, whatever the view. The middle of the object's ground lies on the middle of the icon's box (groundMiddle), so the icon is in line with its name in every view with no rule of its own, because the name lies on the same plane. Seen from straight above only the tops show; on a tilted map the walls show too, and nothing switches between the two. The panes draw the same object from straight above (planSvg, icons/glyph-element.ts).
6. Camera (iso/painting/icon-camera.ts): one rule follows the camera scale, the line width, written once as a function for a still and once as the stylesheet expression for the live map.
7. Names and objects (src/icons.ts, icons/objects/): ICON_KINDS names 151 icons in 13 kinds. A name is an area a part can be about (a map, an order, a diff) or a well-known kind of thing (a database, a queue); the few activity names (search, sync) are for a part whose whole area is that activity. One file per kind holds that kind's objects, typed by the kind's names, so a missing or misspelled name fails the type check. objects/shared-outlines.ts holds the outlines that several kinds draw, and icons/objects.ts joins the kinds. An object is drawn as its picture from above, and each part gets a height. A part lies on the ground, or wholly on the parts under it and starts at their top; a part that covers another and reaches past it starts on the ground too and is higher than what it covers, which is what makes the painter draw it over the other. The foot of a thing that would stand (a monitor's stand, a globe's base) is left out where the picture covers it.
8. Icon field (organisms/choice-field.ts, organisms/icon-picker.ts): a choice can name its heading, and choices with headings make a long field. A long field starts with a switch of two parts, the choice that clears the field (No icon) and the list (Icon). The list stands under a box that filters it by label or heading, and both show only while Icon is on. The switch has one state, whether the list is on, held as the pressed state of the Icon button (aria-pressed), which the stylesheet reads. The list is on from the start when the records share an icon; for records that differ neither part is on. Pressing Icon turns the list on and picks the stored value again, or nothing when the records have none in common; picking No icon turns it off. The filter only hides choices; a hidden choice keeps its radio button, so the pick is still sent. The title names the pick.
9. Names in the terminal (src/write-commands.ts, src/architecture-model.ts): groma edit --help ends with the names, one kind per line, and the refusal of an unknown name points to that list.
10. Tests (test-bun/architecture-icons.test.ts), each with its rule, the wrong result it detects and the gap it closes. Kept: a roof name starts after its icon; an object stays inside its footprint; "the plan of every icon object shows the accent" (wrong: an accent only a tilted view shows, so the drawing from above loses what the object is about; with 151 objects a walk does not catch every one); "an icon is sized from the letters of its name and lies on the name's line, at every size of a title" (wrong: a fixed size, or a box off the line); "no icon drawing before a title reaches what stands on the surface behind it" (wrong: a higher object or a larger ratio lets a drawing cover a building; it now measures from the middle of the box, where the object lies); "on a round roof the icon lies above the name, centred over it"; "a prism shows the faces turned to the reader, and a curved wall is one face". Added on 2026-11-22 from the owner's rule that every icon lies flat on the surface and still shows its depth in Iso: "an icon lies on the map as one object: a tilted map shows the walls of its parts, the view from above only their tops" (wrong: a tilted view that draws no wall, so the icon is a flat sticker, or a view from above that draws walls or other parts than the tilted view; nothing tested which faces a view draws for an icon). Added from a failure the full-context review reproduced in admin, developer and guest: "where two parts of an object overlap, the one that reaches higher is drawn over the other, from above and on a tilted map" (wrong: a lower part drawn over a higher one it overlaps, so the figure of a person card cut its accent badge in every view; the accent test only counts accent shapes, so it passed; checked that the test fails on the former rule, which compared undersides, and passes on the final one). Removed with what they tested: "an icon follows the view of the map" (the two drawings and the switch between them are gone) and "where two panels overlap, the plan shows in front the one the tilted map shows in front" (panels are gone; both views draw the same parts in one order). No test for the Icon field or the help text: the repository has no browser test harness, the field was walked on the live map, and the help text is wording.
11. Docs: the Icons entry and the Element fields entry of docs/viewers/web/index.md, and the Icons section of docs/component-markdown.md with the names by kind.
12. Verification: a sheet of all 151 objects from both views; a script that compares every object's picture from above before and after the rewrite of 2026-11-22; Groma's own map with icons on its elements and groups (demo data on the review map, not committed) in the Iso, 2D and Layers views; the hierarchy rows and the details title; the Edit form's Icon field with No icon, Icon, the filter, Save and the preview on the map; groma edit --help and a refused name; bun run check.
13. The rule for picking an icon (docs/component-markdown.md, docs/agent-instructions/describe.md, src/write-commands.ts): the owner's rule of 2026-11-21, pick the area a part is about and not the action it performs, stands in the contract's Icons section, in the agent guide beside --icon, and as the first line of the names in groma edit --help.
